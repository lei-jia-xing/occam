* Direction (2026-11-06)
Goal: Minimize SQL programs from large-scale fuzz testing while preserving a user-supplied interestingness predicate.
Research question: Can SQL state dependencies reduce DBMS executions and reset costs while producing smaller SQL test cases with the same target behavior?
Scope: Existing fuzz SQL, setup state, and an oracle -> reduced SQL that still satisfies that oracle. Collecting real DBMS crashes is not required.
Scale: Both statements per input and inputs per corpus matter.
Order: P0 reliable fuzz-to-reduction -> P1 SQL reduction quality -> P2 corpus throughput -> P3 comparative evaluation.

* 15. P0: Reliable Fuzz-to-Reduction
** DONE Define the existing-fuzz-input and oracle contract
- Accept existing SQL, including schema/setup statements, with a user-supplied external predicate; no new fuzzer or crash collection is required.
- The predicate receives the complete candidate on stdin; exit 0 accepts and every nonzero or signal exit rejects. Output is opaque except the reserved `OCCAM_INFRASTRUCTURE:` diagnostic.
- Require the initial input to pass before reduction; keep synthetic text-marker checks labeled as mechanics only.
** DONE Preserve the supplied generic predicate
- The Occam CLI and evaluator use the same plain predicate contract; no crash signature, failure-any mode, or crash-specific metadata is required.
- Final checks are uncached and use fresh candidate workdirs; two final validations run when budgets permit.
- Verified smoke: Python stdlib SQLite reduced 44 statements/1,518 bytes to 3/149 while preserving `SELECT` result 42; the initial check ran once, final checks twice, and 57 distinct workdirs were observed across the run and adapter recheck. False, exit-139, and TERM predicates rejected before reduction.
** DONE Bound oracle I/O and define the isolation boundary
- Each observation gets a fresh `OCCAM_WORKDIR` (also used for `TMP`, `TMPDIR`, and `TEMP`); reset and predicate share it, while cwd is preserved and exported as `OCCAM_ORIGINAL_CWD`.
- Haskell oracle output is drained while stdin is written concurrently; raw-byte marker scanning crosses chunks and retains only bounded diagnostics (up to 2 MiB). The benchmark wrapper keeps 8-KiB audit tails plus bounded marker diagnostics.
- Linux real-process checks covered binary stdin, multi-megabyte output, early/late split markers, timeouts, and cleanup of owned process groups. Only owned POSIX groups are guaranteed: escaped descendants (including `setsid`) and full Windows process-tree cleanup remain outside the verified scope. Occam does not guarantee real DB reset/state isolation; the external reset/predicate owns database state.
** IN_PROGRESS [#A] Bound each reduction and record useful metrics
- Per-call timeout, total wall-clock budget, and uncached oracle-execution budget include initial and final checks.
- Preserve the last accepted SQL on exhaustion and return nonzero; run two uncached final validations when budgets permit. `stats.json` reports actual status and available measurements; token counts may be unknown.
- `evaluationPreflightResetSeconds` and `evaluationPreflightOracleSeconds` describe the initial/preflight check; `evaluationResetSeconds` measures reduction resets; `evaluationValidationResetSeconds` measures final-validation resets. These phases are separate. Unavailable optional preflight measurements serialize as `null`.
- Reserve final-validation wall time only for calls actually scheduled; zero scheduled validations reserve zero. If preflight consumes the execution cap, report `execution-budget`, make no reduction or final calls, and preserve the accepted checkpoint.
- Extend and evaluate useful per-input metrics (including reset cost and corpus throughput); keep text-predicate results separate from DB-executing predicates.

* 19. Related Work (2026-11-06)
- SQLancer: statement DD and JSQLParser AST reductions; requires a `Reproducer`.
  https://github.com/sqlancer/sqlancer/blob/main/docs/testCaseReduction.md
- SQLreduce: PostgreSQL/pglast query reduction preserving errors or SQLSTATE.
  https://github.com/credativ/sqlreduce
- ProbDD (FSE 2021): deletion selection using previous test results.
  https://github.com/Amocy-Wang/ProbDD
- CDD (ICSE 2025): a simpler alternative to ProbDD.
  https://arxiv.org/abs/2408.04735
- WDD (ICSE 2025): size-weighted partitions for ddmin and ProbDD.
  https://arxiv.org/abs/2411.19410
- Perses: syntax-guided reduction; verify SQL support at the selected revision.
  https://github.com/uw-pluverse/perses

- Contrast its user/provider reconstruction with SQL schema generations, transactional state, conservative fallback, and byte-preserving reduction; do not compare the paper's C/Java results as SQL measurements.
