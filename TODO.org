* Direction (2026-11-06)
Goal: Minimize SQL programs from large-scale fuzz testing while preserving a user-supplied interestingness predicate.
Research question: Can SQL state dependencies reduce DBMS executions and reset costs while producing smaller SQL test cases with the same target behavior?
Scope: Existing fuzz SQL, setup state, and an oracle -> reduced SQL that still satisfies that oracle. Collecting real DBMS crashes is not required.
Scale: Both statements per input and inputs per corpus matter.
Order: Reliable fuzz-to-reduction -> SQL reduction quality -> Large-scale workloads -> Comparative evaluation -> Formal verification.
